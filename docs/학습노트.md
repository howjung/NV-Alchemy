## 1. 전체 구조

```
Flutter 앱 ──▶ Render (Node.js 서버) ──▶ Supabase (PostgreSQL)
 화면, 입력        검사, 로직, 인증            데이터 저장
```

| 이름 | 역할 | 식당 비유 |
| --- | --- | --- |
| Flutter | 앱 화면을 만들고 입력을 받음 | 홀 |
| Node.js | 서버 코드를 실행하는 프로그램 | 주방 |
| NestJS | Node.js 서버 코드를 정리해서 만들게 해 주는 틀 | 주방의 업무 분담표 |
| TypeScript | 타입이 있는 JavaScript. 오타·타입 실수를 미리 알려 줌 | - |
| PostgreSQL | 데이터를 저장하는 DB | 창고 |
| SQL | DB에 저장·조회를 시키는 언어 | 입출고 지시서 |
| TypeORM | TypeScript 코드를 SQL로 바꿔 주는 도구 | 지시서 대필 |
| Supabase | PostgreSQL을 인터넷에서 빌려주는 서비스 | 외부 창고 |
| Render | 서버를 인터넷에서 실행해 주는 서비스 | 가게 자리 |

Docker는 더 이상 쓰지 않는다(예전에는 내 PC에서 DB를 돌릴 때 사용).

**앱은 DB에 직접 접속하지 않는다.** DB 비밀번호가 앱에 들어가면 안 되고, "남의 기록 보기" 같은 것을 서버에서 막아야 하기 때문이다.

### ② `.env` 만들기

### ③ DB 연결 — `src/app.module.ts`
```ts
ConfigModule.forRoot({ isGlobal: true }),
TypeOrmModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (config: ConfigService) => ({
    type: 'postgres' as const,
    url: config.getOrThrow<string>('DATABASE_URL'),
    ssl: { rejectUnauthorized: false },
    autoLoadEntities: true,
    synchronize: true,
  }),
}),
```
| 코드 | 뜻 |
| --- | --- |
| `forRootAsync` | `.env`를 읽은 뒤에 DB 설정을 만든다 |
| `getOrThrow` | 값이 없으면 바로 오류 |
| `ssl` | 암호화 접속. 지금은 서버 인증서를 검증하지 않음(나중에 보완) |
| `autoLoadEntities` | module에 등록한 entity를 자동으로 사용 |
| `synchronize` | entity에 맞춰 테이블을 자동 변경. **컬럼이 지워질 수 있어 개발 초기에만** |

### ⑤-2 가입·로그인
예전 서버의 코드를 가져왔다(`git show 브랜치:파일 > 파일`).

**가입** `POST /auth/signup`
```
입력 검사(DTO) → 이메일 중복 확인 → 비밀번호 해시 → DB 저장 → 토큰 발급
```
**로그인 후 요청**
```
Authorization: Bearer <토큰> → AuthGuard가 서명·만료 검사 → userId 꺼냄 → controller
```

| 파일 | 역할 |
| --- | --- |
| `auth/password.ts` | `scrypt` 해시. 사용자마다 다른 솔트를 붙여 `솔트:해시`로 저장 |
| `auth/auth.service.ts` | 가입, 로그인, 토큰 발급(7일). 토큰에는 유저 번호만 넣음 |
| `auth/auth.guard.ts` | 문지기. 모든 요청의 토큰 검사 |
| `auth/public.decorator.ts` | `@Public()`: 로그인 없이 쓸 수 있는 API 표시 |
| `auth/user-id.decorator.ts` | `@UserId()`: 토큰에서 나온 내 번호 받기 |
| `auth/dto/*.dto.ts` | 입력 규칙 |

- `app.module.ts`에서 `APP_GUARD`로 문지기를 **전체에** 적용했다. 그래서 기본은 "로그인 필요"이고, `/`, `/notices`, `/auth/*`에만 `@Public()`을 붙였다.
- 이메일이 없을 때와 비밀번호가 틀렸을 때 **같은 메시지**를 준다(가입 여부를 알아내지 못하게).
- `passwordHash`는 `select: false`라서 평소 조회 결과에 포함되지 않는다.

### ⑧ 연속 기록 API (11-27)
앱 홈 화면(히어로)이 연속 기록에 따라 바뀌어야 해서 만들었다. **서버가 계산하고 앱은 보여주기만** 한다.

```

```

| 마지막 기록 | 결과 |
| --- | --- |
| 오늘 | 오늘을 포함해 센 일수, `recordedToday: true` |
| 어제 | 일수 유지, `recordedToday: false` |
| 그제 이전 | `days: 0`, `broken: true` (물방울이 어는 상태) |
| 기록 없음(신규) | `days: 0`, `broken: false` |

보상 단계: 3·7·14·30·50·100일

| 파일 | 역할 |
| --- | --- |
| `streak/entities/record-day.entity.ts` | 기록한 날짜 테이블. `userId`+`date`가 함께 기본키라 같은 날짜는 한 줄 |
| `streak/streak.ts` | `todayKst()`, `calcStreak()` 계산 |
| `streak/streak.service.ts`, `.controller.ts`, `.module.ts` | `GET /streak` |
| `streak/streak.spec.ts` | 계산 테스트 6개 |
| `meals/meals.service.ts` | 오늘 날짜만 저장, 날짜 변경 금지, 식단과 기록 날짜를 트랜잭션으로 저장 |
| `users/users.service.ts` | 탈퇴 때 기록 날짜도 삭제 |

배운 것
- **한국 시간:** 서버 시계는 다른 나라 기준일 수 있어 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })`로 오늘을 구한다.
- **계산 분리:** DB 없이 계산만 하는 함수로 만들면 "어제", "끊김" 같은 경우를 쉽게 테스트할 수 있다.
- **정책:** 식단을 삭제해도 연속 기록은 유지(그래서 별도 테이블). 식단은 오늘만 기록. 두 정책은 PRD에서 팀 확정이 필요하다.
- 이 기능을 만들기 전에 저장한 식단은 연속 기록에 반영되지 않는다.

적용한 방법: 변경 내용을 담은 patch 파일을 `git apply <파일>`로 적용하고 `git diff`로 확인.

확인
```bash
npm test -- streak                                  # 계산 테스트
node test/streak-smoke.mjs                          # 서버 동작(서버를 켠 상태에서)
```
배포 서버에서도 `BASE_URL=https://<내 서비스>.onrender.com node test/streak-smoke.mjs`가 통과했다(11-27).

### ⑨ 놓친 날 수 `missedDays` (11-27)

앱 홈의 물방울은 놓친 날이 많을수록 더 언다(1일, 2일, 3일 이상). `broken`(끊김 여부)만으로는 구분할 수 없어서 값을 하나 더 보낸다.

적용 (서버 폴더에서):
```bash
git apply ../missed-days.patch
npm test -- streak
```
바뀌는 곳은 `streak.ts`의 계산 한 줄과 테스트 두 파일이다.

```ts
// 마지막 기록 뒤로 통째로 건너뛴 날 수. 오늘은 아직 놓친 것이 아니라서 1을 뺀다
const missedDays = recorded.size ? Math.max(0, now - Math.max(...recorded) - 1) : 0;
```

| 마지막 기록 | `missedDays` |
| --- | --- |
| 오늘 또는 어제 | 0 |
| 그저께 | 1 |
| 3일 전 | 2 |
| 기록 없음 | 0 |

`Math.max(0, …)`가 없으면 오늘 기록했을 때 -1이 나온다. 올린 뒤 Render 배포가 끝나면 `test/streak-smoke.mjs`로 확인한다.

## 4. 겪은 오류와 해결

| 증상 | 원인 | 해결·교훈 |
| --- | --- | --- |
| `has no exported member 'ObserveInstrument'` | 지운 이름을 다른 파일이 계속 가져옴 | `export`를 지우면 `import`하는 곳도 확인 |
| `Cannot find name 'AppModul'` | `e`가 빠짐 | "Cannot find name"은 철자부터 |
| `npm audit` 취약점 경고 | 설치한 패키지의 알려진 문제 | `npm audit fix --force`는 함부로 실행하지 않기 |
| `.env` 연결 문자열 | 비밀번호에 `[ ]`가 남음 | 괄호는 자리 표시라 지운다 |
| `EADDRINUSE :::3000` | 서버를 두 번 켬 | 하나만 남기고 `Ctrl+C` |
| `Cannot find module './entities/notice.entity'` | 파일 이름이 `notice.entit.ts` | "Cannot find module"은 파일 이름과 경로 확인 |
| 고쳤는데 빨간 줄이 남음 | 편집기가 이름 변경을 반영 못 함 | `Cmd+Shift+P` → TS 서버 다시 시작 |
| `/`가 계속 `Hello World!` | 정상. 주소마다 담당 controller가 다름 | 공지는 `/notices` |
| `/notices`가 401 | `app.controller.ts`에 공지 controller 코드를 덮어써 컴파일 실패, 서버가 이전 상태로 응답 | 붙여넣기 전에 파일 이름 확인. 터미널의 오류부터 보기 |
| 배포 주소가 응답 없음 | Render의 `DATABASE_URL`에 값 대신 **명령어**를 넣음 | 명령어는 터미널에서 실행하고, 복사된 **결과**를 붙여넣기 |
| 올린 직후 배포 서버의 `/streak`이 404 | 새 코드가 아직 배포되기 전 | Render **Events**에서 배포 완료를 기다린 뒤 확인 |
| `npm test`에서 `app.controller.spec.ts` 실패(`Must use import to load ES Module`) | 처음부터 있던 테스트가 Node 22의 모듈 방식과 맞지 않음 (아직 고치지 않음) | 지금은 `npm test -- streak`처럼 골라 실행 |

## 5. NestJS 핵심 개념

| 파일 | 역할 |
| --- | --- |
| `main.ts` | 서버를 켜는 시작점. 전체 설정, `listen(포트)` |
| `app.module.ts` | 어떤 부품을 쓸지 묶는 목록 |
| `*.controller.ts` | **어떤 주소**의 요청을 받을지 |
| `*.service.ts` | **실제로 할 일** |
| `*.module.ts` | 기능 하나의 controller와 service를 묶음 |
| `*.entity.ts` | DB 테이블의 모양 |
| `*.dto.ts` | 요청으로 받을 값의 모양과 규칙 |

| 용어 | 뜻 |
| --- | --- |
| 데코레이터 (`@Get()` 등) | 클래스나 메서드에 역할을 붙이는 표시 |
| `@Injectable()` | 다른 곳에서 가져다 쓸 수 있는 부품 |
| 의존성 주입 | `constructor`에 적으면 NestJS가 객체를 만들어 넣어 줌 |
| Repository | 테이블 하나를 다루는 도구(`find`, `save`, `delete`) |
| Guard | 요청이 controller에 가기 전에 통과 여부를 정함 |
| ValidationPipe | 요청 값이 DTO 규칙에 맞는지 검사 |
| JWT | 서버가 서명한 로그인 증표 |
| 해시 | 원래 값으로 되돌릴 수 없게 바꾼 값 |
| 트랜잭션 | 여러 작업을 전부 성공하거나 전부 취소 |

| 메서드 | 용도 | | 코드 | 뜻 |
| --- | --- | --- | --- | --- |
| GET | 조회 | | 200 / 201 | 성공 / 만들기 성공 |
| POST | 만들기 | | 400 | 보낸 값이 잘못됨 |
| PATCH | 일부 수정 | | 401 | 로그인 필요 |
| DELETE | 삭제 | | 404 / 409 | 없음 / 중복 |
| | | | 500 | 서버 오류 |
