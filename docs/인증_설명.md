# 서버 인증 설명

팀원 누구나 읽고 설명할 수 있도록 쓴 문서다. 코드는 `src/auth/`에 있다.

## 한 줄 요약

가입·로그인하면 서버가 **출입증(토큰)**을 주고, 이후 모든 요청은 출입증을 보여줘야 한다. 서버는 출입증으로 "누구의 요청인지" 알아내서 **그 사람의 데이터만** 돌려준다.

## 흐름

```
앱                                   서버
 │  POST /auth/signup (이메일·비번·닉네임) │
 │ ─────────────────────────────────────▶ 입력 검사 → 비번 암호화 저장 → 토큰 발급
 │ ◀───────────────  { accessToken, user } │
 │                                         │
 │  GET /weights                           │
 │  Authorization: Bearer <토큰>           │
 │ ─────────────────────────────────────▶ 문지기가 토큰 검사 → 유저 번호 꺼냄
 │ ◀───────────────  내 체중 기록만         │   → 그 번호의 데이터만 조회
```

## 파일별 역할

| 파일 | 하는 일 |
| --- | --- |
| `auth.controller.ts` | `POST /auth/signup`, `POST /auth/login`. 로그인 없이 호출 가능(`@Public`) |
| `auth.service.ts` | 가입(중복 이메일 거부, 비번 암호화), 로그인(비번 확인), 토큰 발급 |
| `password.ts` | 비밀번호를 `솔트:해시`로 바꿔 저장하고, 로그인 때 비교한다. 원문은 저장하지 않는다 |
| `auth.guard.ts` | **문지기.** 모든 요청에서 토큰을 검사한다. 없거나 위조·만료면 401 |
| `public.decorator.ts` | 문지기를 통과시킬 API에 붙이는 표시. 붙이지 않으면 기본이 "로그인 필요" |
| `user-id.decorator.ts` | 컨트롤러에서 `@UserId()`로 "지금 요청한 사람의 번호"를 받는다 |
| `dto/*.dto.ts` | 입력 규칙(비번 8자 이상, 닉네임 2~12자 등). 어기면 400 |

## 핵심 개념 4가지

1. **비밀번호 해시**: 비밀번호를 암호화해서 저장한다. DB가 유출돼도 원문을 알 수 없다. 사용자마다 다른 난수(솔트)를 섞어서 같은 비번도 저장값이 다르다.
2. **토큰(JWT)**: 서버가 비밀키로 서명한 출입증이다. 안에는 유저 번호만 들어 있고, 서명 때문에 앱이 번호를 바꾸면 검사에서 걸린다. 7일 뒤 만료된다.
3. **문지기(Guard)**: 컨트롤러에 도착하기 전에 모든 요청을 검사한다. 앞으로 만드는 API는 따로 신경 쓰지 않아도 기본이 "로그인 필요"다.
4. **`userId`를 body로 받지 않는다**: 이전에는 앱이 `userId`를 적어 보내서 남의 기록을 볼 수 있었다. 이제는 토큰에서 번호를 꺼낸다. body에 `userId`를 넣어도 무시된다(`whitelist`).

## API 변경점 (기존 서버 대비)

| 이전 | 이후 |
| --- | --- |
| `POST /users` 로 유저 생성 (이메일·닉네임만) | `POST /auth/signup` (비밀번호 포함). `/users` CRUD는 삭제 |
| 유저 정보 `GET/PATCH/DELETE /users/:id` | `GET/PATCH/DELETE /users/me` (나만) |
| `weights`·`meals` 요청에 `userId` 포함, 목록은 전체 | `userId` 제거, 목록·조회·수정·삭제 모두 내 기록만. 남의 기록은 404 |
| 입력 검사 없음 | 키 100~250, 체중 20~300, 닉네임 2~12자, 비번 8자+, 만 14~100세, 끼니 4종 |
| 체중은 같은 날 여러 건 | 같은 날 다시 입력하면 마지막 값으로 덮어쓰기 |
| 로그인 없이 모든 API 호출 가능 | 가입·로그인 외에는 토큰 필요(사진 업로드 포함) |

온보딩에서 받는 성별·생년월일·키·목표 체중은 가입 후 `PATCH /users/me`로 저장한다.

## 실행과 확인

```bash
cp .env.example .env     # JWT_SECRET 포함
npm run start:dev        # 서버 실행
npm run test:smoke       # 다른 터미널에서. 인증·범위·남의 기록 차단을 한 번에 확인
```

## 아직 하지 않은 것 (알고 있어야 하는 한계)

- **토큰 재발급·로그아웃 폐기 없음**: 토큰이 7일 동안 유효하다. 로그아웃은 앱이 토큰을 지우는 것으로만 처리된다. 필요해지면 refresh 토큰을 추가한다.
- **로그인 시도 횟수 제한 없음**: 비밀번호를 계속 시도할 수 있다. 운영 전에 `@nestjs/throttler`를 붙인다.
- **비밀번호 재설정·변경 API 없음**: 앱 화면은 있지만 서버 쪽은 아직이다.
- **`JWT_SECRET`은 개발용 값**: 운영에서는 긴 난수로 바꾸고 `.env`는 git에 올리지 않는다.
- **탈퇴는 계정·체중·식단만 삭제**: 주문 익명화·포인트 소멸은 쇼핑 API가 생길 때 같이 한다.
- **jest 단위 테스트는 기존 설정 문제로 동작하지 않아 제거**했고, 대신 `test/auth-smoke.mjs`로 확인한다.
