## 사용 방법

1. 아래 프롬프트를 1단계부터 순서대로 하나씩 입력한다. 5단계는 5-1(소셜), 5-2(프로필 나머지·마무리) 순서로 두 번 입력한다.
2. 단계가 끝나면 서버와 앱을 실행해서 동작과 소스를 확인한다. 완료 기준을 하나씩 점검한다.
3. 다음 프롬프트에 반영할 내용(확정된 결정, 수정사항)이 있으면 고쳐서 입력한다.
4. 단위테스트를 마치고 로컬 저장소에 `git commit` 한다. 커밋 메시지는 각 단계에 적어 두었다.
5. 5단계가 끝나면 프로젝트 공용 GitHub로 옮기고 통합테스트를 한다.

## 1단계. 서버·앱 세팅 · DB · 인증 · 온보딩 · 약관 화면

화면(11개): SPLASH, AUTH-03 로그인, AUTH-02 회원가입(약관 동의), AUTH-04 비밀번호 찾기, 시작 04b 비밀번호 찾기 · 전송 완료, ONB-01 프로필 정보, ONB-01 생년월일 선택 시트, ONB-02 신체 정보와 목표, 프로필 07 서비스 이용약관, 프로필 17 개인정보 처리방침, 프로필 20 오픈소스 라이선스
기능: #1 회원가입·로그인, #2 초기 프로필, 세션 유지, 비밀번호 찾기, 약관

```
[1단계] 서버와 앱을 세팅하고, 인증과 온보딩, 약관 정적 화면을 만들어줘.

1. 서버 세팅
- server 폴더에 Express + TypeScript 프로젝트를 만들고 pg, bcrypt, jsonwebtoken, zod, jest, supertest를 설치해줘.
- .env.example에 DB 접속 정보, JWT 비밀키, Gemini API 키 자리를 만들어줘.
- migrations 폴더에 SQL 마이그레이션을 만들고 실행하는 스크립트를 넣어줘.
- 공통 에러 응답 형식 { success, message, data }을 정하고 에러 처리 미들웨어를 만들어줘.

2. DB (PostgreSQL)
- users(이메일, 비밀번호 해시, 닉네임, 생년월일, 성별, 선호 식단 방식 ENUM: 완제품/밀키트/혼합(값 없음 허용), 약관 동의 일시)와 goals(목표 변화, 키, 현재 체중, 목표 체중, 활동량 ENUM, BMR, 권장 칼로리) 테이블을 만들어줘.
- 선호 식단 방식은 온보딩 화면에서 입력받지 않는다(프로필 06에서 설정, 4단계). 온보딩에서 정할지는 (확정 필요, N22)이므로 컬럼만 두고 TODO로 표시해줘.
- refresh token을 폐기할 수 있도록 refresh token 저장(또는 폐기 목록) 테이블과, 비밀번호 재설정 요청을 저장할 자리(테이블 또는 컬럼)를 만들어줘.

3. 인증 API
- GET /auth/email-check?email=: 이메일 중복 확인 API를 만들어줘.
- POST /auth/register: 이메일, 비밀번호, 비밀번호 확인, 약관 동의(필수)를 받아줘. 이메일이 중복이면 가입 시에도 한 번 더 검사해서 실패 사유를 돌려줘.
- POST /auth/login, POST /auth/refresh를 만들어줘. access token은 30분, refresh token은 14일로 둬줘(상수 파일에 모아줘). 실패 사유(잘못된 정보, 서버 오류)를 구분해서 돌려줘.
- POST /auth/logout: 해당 refresh token을 폐기해줘. 폐기된 refresh token으로 재발급하면 401을 돌려줘.
- POST /auth/password-reset: 가입한 이메일로 재설정 링크를 발송하는 API(전송 완료 화면의 "다시 보내기"도 이 API를 다시 호출한다). 재설정 링크 방식과 만료 시간은 서버 구현 시 정하는 항목이므로 이메일 발송은 어댑터 함수로 분리하고(개발 환경에서는 콘솔 출력), 링크 방식과 만료 시간은 설정값으로 두고 TODO로 표시해줘.
- 인증 미들웨어를 만들어 토큰이 없거나 무효면 401을 돌려줘. 이후 모든 API는 본인 데이터만 다루게 해줘.

4. 프로필 API
- PUT /me/profile: 닉네임, 생년월일, 성별, 목표 변화, 활동량, 키, 현재 체중, 목표 체중을 받아줘.
- BMR은 Mifflin-St Jeor 공식으로 계산해줘. 남성은 10×체중 + 6.25×키 − 5×나이 + 5, 여성은 마지막 항이 −161이다.
- 권장 칼로리 = BMR × 활동계수이고, 활동량 4단계의 계수는 1.2 / 1.375 / 1.55 / 1.725다. 하한은 남성 1500, 여성 1200 kcal이며 계산값이 하한 미만이면 하한으로 저장한다. 계산 함수와 상수는 파일 하나에 모아줘. 활동량 선택지 이름과 목표 감량의 권장 칼로리 반영 여부는 (확정 필요)이므로 TODO로 표시하고, 감량은 반영하지 않는다.
- 목표 변화(예: -6kg 감량)와 목표 체중의 관계는 (확정 필요, N21)이다. 둘 다 입력받아 저장만 하고 서로 계산하지 말고 TODO로 표시해줘.
- 입력 범위는 서버(zod)와 앱 양쪽에서 검증해줘: 키 100~250cm, 체중·목표 체중 20~300kg, 닉네임 2~12자, 비밀번호 8자 이상. 생년월일은 ONB-01 시트 안내 범위(오늘 기준 만 10~100세로 보임)를 설정값으로 두고, 최소 가입 연령은 (확정 필요, N23)이므로 TODO로 표시해줘. 필수 값 누락, 음수, 범위 밖 값은 400과 사유를 돌려줘. 범위 수치는 상수 파일 하나에 모아줘.

5. Flutter 앱
- app 폴더에 Flutter 프로젝트를 만들고 하단 탭(홈/기록/소셜/쇼핑/프로필) 5개 뼈대와 라우팅을 만들어줘. 탭 화면은 비어 있어도 된다.
- SPLASH: 앱 시작 화면. 이후 로그인 상태에 따라 AUTH-03 또는 홈으로 이동한다.
- AUTH-03 로그인(비밀번호 찾기·회원가입 링크, 실패 사유 표시), AUTH-02 회원가입(이메일·비밀번호·비밀번호 확인, 약관 동의 후 "다음", 이메일 중복 확인 버튼으로 email-check 호출), AUTH-04 비밀번호 찾기와 전송 완료 화면("로그인으로 돌아가기", "다시 보내기")을 만들고 서버 API를 연결해줘.
- ONB-01 프로필 정보(닉네임, 생년월일은 선택 시트, 성별. 생년월일·성별은 권장 칼로리 계산에만 쓰이고 다른 사람에게 보이지 않는다는 안내 문구, 닉네임은 크루 피드·댓글에 보인다는 점), ONB-02 신체 정보와 목표(목표 변화, 활동량, 키, 현재 체중, 목표 체중)를 만들고 서버 API를 연결해줘.
- 프로필 07 서비스 이용약관, 프로필 17 개인정보 처리방침, 프로필 20 오픈소스 라이선스는 정적 문서 화면으로 만들어줘. AUTH-02의 약관 동의에서 07·17로 연결한다. 본문 출처는 (확정 필요, N19)이므로 자리용 문구를 넣고 TODO로 표시해줘. 프로필 메인에서의 진입은 2단계에서 연결한다.
- 흐름은 SPLASH → AUTH-03. AUTH-03 → AUTH-02 또는 AUTH-04 → 전송 완료 → AUTH-03. AUTH-02 → ONB-01 → ONB-02 → 홈이다. 기존 사용자는 AUTH-03에서 홈으로 바로 이동한다.
- 토큰을 안전하게 저장하고(flutter_secure_storage), 만료되면 refresh로 재발급하고, 무효면 AUTH-03으로 보내줘.

- 로그아웃은 refresh 폐기 API까지만 만들고 로그아웃 화면·팝업은 5-2단계에서 다룬다.

```
[2단계] 홈·기록 탭, 식단·체중 기록, 포인트 적립, 연속 기록, 알림 목록, 프로필 메인을 만들어줘. 1단계의 인증과 프로필을 그대로 사용해줘.

**완료 기준**
- 크루 생성 → 신청 대기 → 수락 → 인증 글 → 불꽃 보내기·댓글 → 크루 연속 인증 +1 흐름이 끊김 없이 동작한다. 가입 완료 멤버 전원이 인증하면 크루 연속 인증이 이어지고, 한 명이라도 빠지면 0으로 초기화된다.
- "크루만 공개" 게시물을 해당 크루 가입 완료 멤버가 아닌 사용자가 조회할 수 없다. 비공개 게시물은 작성자만 본다.
- 좋아요는 게시글당 사용자 1회만 토글된다.
- 한 사용자는 한 크루에만 가입할 수 있고, 정원이 찬 크루와 이미 가입한 사용자의 신청은 사유와 함께 거부된다.
- 게시물 메뉴에서 신고하기를 선택하면 신고가 접수된다.
- 접근 규칙, 크루 연속 인증 판정, 좋아요 토글에 테스트가 있고 통과한다.
