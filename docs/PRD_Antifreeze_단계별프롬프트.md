## 사용 방법

1. 아래 프롬프트를 1단계부터 순서대로 하나씩 입력한다.
2. 단계가 끝나면 서버와 앱을 실행해서 동작과 소스를 확인한다. 완료 기준을 하나씩 점검한다.
3. 다음 프롬프트에 반영할 내용(확정된 결정, 수정사항)이 있으면 고쳐서 입력한다.
4. 단위테스트를 마치고 로컬 저장소에 `git commit` 한다. 커밋 메시지는 각 단계에 적어 두었다.
5. 5단계가 끝나면 프로젝트 공용 GitHub로 옮기고 통합테스트를 한다.

```
antifreeze/
```

## 공통 규칙 (매 단계 프롬프트 앞에 붙인다)

```
프로젝트: Antifreeze (AI 식단 추천 + 식단 기록 + 크루 소셜 + 쇼핑·정기구독 + 포인트 앱)
기술 스택:
- 앱: Flutter (Dart). 상태관리 Riverpod, 라우팅 go_router, HTTP는 dio.
- 서버: Node.js + Express (TypeScript). PostgreSQL은 node-postgres(pg)로 접근하고, 스키마는 SQL 마이그레이션 파일로 관리한다.
- 인증: 이메일·비밀번호, bcrypt 해시, JWT(access + refresh).
- AI: Gemini API. 호출은 서버에서만 하고 API 키는 서버 환경변수에만 둔다.
- 테스트: 서버는 jest + supertest.
규칙:
- 화면은 Figma 와이어프레임(화면 ID 기준)을 따른다. 하단 탭은 홈/크루/쇼핑/마이 4개다.
- 전체화면, 바텀시트, 모달 구분은 화면 ID에 적힌 유형을 따른다.
- 모든 쓰기 실패 시 입력 내용을 유지하고 실패 사유를 화면에 보여준다.
- 서버와 앱 양쪽에서 입력값을 검증한다. 필수 값 누락, 음수, 범위 초과를 막는다.
- 이미지는 서버 파일 저장소에 두고 DB에는 경로만 저장한다. 주문 상태 같은 상태값은 ENUM으로 만든다.
- 이번 단계 범위 밖의 기능은 만들지 않는다. 이전 단계 코드는 필요한 부분만 수정한다.
- 변경한 파일 목록과 실행 방법을 마지막에 요약한다.
MVP에서 제외: 소셜 로그인, AI 추천 이력 저장, 벌점·랭킹.
```

## 1단계. 서버·앱 세팅 · DB · 인증 · 온보딩

화면: ONB-01 로그인·회원가입, ONB-02 사용자 정보 기록, ONB-03 취향 설정
기능: #1 회원가입·로그인, 세션 유지, #2 초기 프로필, #3 식단 취향

```
[1단계] 서버와 앱을 세팅하고, 인증과 온보딩을 만들어줘.

1. 서버 세팅
- server 폴더에 Express + TypeScript 프로젝트를 만들고 pg, bcrypt, jsonwebtoken, zod, jest, supertest를 설치해줘.
- .env.example에 DB 접속 정보, JWT 비밀키, Gemini API 키 자리를 만들어줘.
- migrations 폴더에 SQL 마이그레이션을 만들고 실행하는 스크립트를 넣어줘.
- 공통 에러 응답 형식 { success, message, data }을 정하고 에러 처리 미들웨어를 만들어줘.

2. DB (PostgreSQL)
- users(이메일, 비밀번호 해시, 닉네임, 생년월일, 성별, 선호 식단 방식 ENUM: 완제품/밀키트/혼합, 약관 동의 일시)와 goals(키, 현재 체중, 목표 체중, 활동량 ENUM, BMR, 권장 칼로리) 테이블을 만들어줘.

3. 인증 API
- POST /auth/register: 약관 동의 필수, 이메일 중복이면 실패 사유를 돌려줘.
- POST /auth/login, POST /auth/refresh를 만들어줘. access token은 짧게, refresh token은 길게 둬줘.
- 인증 미들웨어를 만들어 토큰이 없거나 무효면 401을 돌려줘. 이후 모든 API는 본인 데이터만 다루게 해줘.

4. 프로필 API
- PUT /me/profile: 성별, 나이(생년월일), 키, 현재 체중, 목표 체중, 활동량을 받아줘.
- BMR은 Mifflin-St Jeor 공식으로 계산해줘. 남성은 10×체중 + 6.25×키 − 5×나이 + 5, 여성은 마지막 항이 −161이다.
- 활동계수는 1.2 / 1.375 / 1.55 / 1.725를 곱해 권장 칼로리를 구하고, 하한은 남성 1500, 여성 1200 kcal로 해줘. 계산 함수와 상수는 파일 하나에 모아줘.
- PUT /me/preference: 선호 식단 방식을 저장해줘.
- 필수 값 누락, 음수, 허용 범위 밖 값(키·체중·나이)은 400과 사유를 돌려줘.

5. Flutter 앱
- app 폴더에 Flutter 프로젝트를 만들고 하단 탭(홈/크루/쇼핑/마이) 뼈대와 라우팅을 만들어줘. 탭 화면은 비어 있어도 된다.
- ONB-01 로그인·회원가입 화면, ONB-02 사용자 정보 기록 화면, ONB-03 취향 설정 화면을 만들고 서버 API를 연결해줘.
- 흐름은 ONB-01 → ONB-02 → ONB-03 → 홈이다. 기존 사용자는 홈으로 바로 이동한다.
- 토큰을 안전하게 저장하고(flutter_secure_storage), 만료되면 refresh로 재발급하고, 무효면 로그인 화면으로 보내줘.
- 입력 중 뒤로 가기를 눌러도 입력한 값이 사라지지 않게 해줘.
```

**완료 기준**
- 가입 → 온보딩 → 홈 이동이 되고, 앱을 다시 켜도 로그인이 유지된다.
- 잘못된 입력은 저장되지 않고 사유가 보인다.
- DB에 비밀번호가 평문으로 저장되지 않는다.
- BMR·권장 칼로리 계산과 인증 API에 테스트가 있고 통과한다.

**커밋 메시지:** `feat: 서버·앱 세팅, 이메일 인증, 온보딩`

## 2단계. 식단·체중 기록 · 홈 · 포인트 적립 · 체중 그래프

화면: HOM-01 홈 대시보드, HOM-02 식단 퀵 등록, HOM-03 체중 퀵 등록, HOM-04 음식 검색, MYP-01 체중 통계 리포트, MYP-03 포인트 내역
기능: #4, #5, #6, #18, 포인트 적립, 스트릭

```
[2단계] 식단·체중 기록, 홈 화면, 포인트 적립, 체중 그래프를 만들어줘. 1단계의 인증과 프로필을 그대로 사용해줘.

1. DB
- weight_logs, meal_logs(끼니 ENUM: 아침/점심/저녁/간식, 날짜), meal_items(음식명, 칼로리, 탄수화물, 단백질, 지방, 수량), foods(음식 DB), point_ledger(사용자, 구분 ENUM: 적립/사용, 금액, 사유, 생성일)를 만들어줘.
- foods에는 자주 먹는 음식 30개 정도를 시드로 넣어줘. 외부 공공 API는 쓰지 않는다.

2. 기록 API
- 식단 등록·수정·삭제, 날짜별 조회 API를 만들어줘. 본인 기록만 접근할 수 있어야 한다.
- 체중 등록 API는 하루 한 번만 허용하고, 다시 입력하면 덮어쓰게 해줘. 허용 범위(20~300kg)를 벗어나면 400과 사유를 돌려줘.
- GET /foods?q= 음식 검색 API와 자주 찾는 음식 API를 만들어줘.
- GET /home/summary: 오늘 섭취 칼로리, 목표 칼로리, 탄·단·지 잔여량, 포인트 잔액, 연속 기록 일수를 한 번에 돌려줘.

3. 포인트와 스트릭
- 하루 첫 식단 기록 시 5P를 적립해줘. 1일 1회만 적립한다.
- 연속 기록 일수를 계산해줘. 하루라도 기록이 없으면 0으로 초기화한다. 3·7·14·30·50·100일 마일스톤에 도달하면 보너스를 적립하는 자리를 만들되 보너스 포인트 수치는 상수 파일에 임시값으로 두고 TODO로 표시해줘. 일/주 적립 한도도 같은 방식으로 상수로 둬줘.
- 적립은 식단 저장과 같은 트랜잭션으로 처리해줘.
- GET /points: 잔액과 적립·사용 내역을 돌려줘.

4. Flutter 화면
- HOM-01 홈 대시보드: 오늘 섭취 칼로리 도넛 차트, 탄·단·지 잔여량 프로그레스 바, 포인트 잔액 칩, 연속 기록 표시, + 퀵 등록 버튼을 만들어줘. 크루 미니 배너와 AI 영역은 자리만 두고 비워둬줘.
- HOM-02 식단 퀵 등록(바텀시트): 끼니 선택, 음식 추가·삭제, 저장. 저장 즉시 홈 차트가 갱신되어야 한다.
- HOM-04 음식 검색: 검색창, 결과 리스트(칼로리·탄단지), 자주 찾는 음식, 결과가 없으면 직접 입력 화면으로 이동.
- HOM-03 체중 퀵 등록(바텀시트): 오늘 체중 입력, 지난 기록 대비 변화, BMI 실시간 계산.
- 연속 기록이 끊긴 뒤 홈에 들어오면 안내 팝업을 한 번 보여줘.
- MYP-01 체중 통계 리포트: 프로필 요약, 일/주/월 체중 선 그래프, 목표 달성률, 마이페이지 메뉴 목록(프로필 수정, 내역 관리, 포인트, 알림 설정). 메뉴 항목은 이후 단계에서 연결하므로 지금은 포인트 내역만 연결해줘.
- MYP-03 포인트 적립·사용 내역: 보유 포인트 요약과 내역 리스트.
- 차트는 fl_chart 하나만 써줘. 기록이 없으면 빈 상태 안내를 보여줘.
```

**완료 기준**
- 식단을 저장하면 홈 차트와 포인트 잔액이 바로 바뀐다.
- 같은 날 두 번째 식단을 기록해도 포인트가 중복 적립되지 않는다.
- 같은 날 체중을 두 번 입력하면 마지막 값만 남는다.
- 연속 기록 계산(연속, 끊김 초기화)에 테스트가 있고 통과한다.

**커밋 메시지:** `feat: 식단·체중 기록, 홈 대시보드, 포인트 적립, 체중 그래프`

## 3단계. 쇼핑 · 단축 구매 · 포인트 사용

화면: SHO-01 쇼핑 상품 목록 메인, SHO-03 상품 상세정보, SHO-02 단축 구매
기능: #13, #14, 포인트 사용

```
[3단계] 쇼핑 탭의 상품 목록, 상세, 단축 구매와 포인트 사용을 만들어줘.

1. DB
- product_categories(완제품, 밀키트), products(이름, 설명, 가격, 이미지 경로, 칼로리, 탄·단·지, 카테고리), addresses, payment_methods, orders(상태 ENUM: 결제완료/배송중/배송완료/취소, 사용 포인트, 결제 금액), order_items를 만들어줘.
- products 시드 데이터 10개(완제품 6, 밀키트 4)를 넣어줘.

2. 쇼핑 API
- GET /products?category=: 카테고리별 목록 API. 정렬(낮은 가격순)과 내 식단에 맞는 상품만 보기 필터를 지원해줘. AI 추천순과 적합도는 4단계에서 붙이므로 지금은 자리만 두고 비워둬줘.
- GET /products/:id: 상품 상세와 영양 정보.
- 배송지·결제 수단 등록·조회 API. 결제 수단은 실제 카드 정보를 저장하지 않고 표시용 이름만 저장해줘.

3. 주문 API
- POST /orders: 상품, 수량, 배송지, 결제 수단, 사용 포인트를 받아줘.
- 가격과 금액은 서버가 다시 계산하고 클라이언트가 보낸 금액은 믿지 않는다.
- 포인트는 1P = 1원, 500P부터 100P 단위로, 결제 금액까지만 쓸 수 있다. 규칙에 어긋나면 400과 사유를 돌려줘.
- 결제는 모의 결제로 처리해줘. 결제 함수는 별도 모듈로 분리해서 나중에 실결제로 바꿀 수 있게 해줘.
- 주문 생성, 포인트 차감, point_ledger 기록은 하나의 트랜잭션으로 처리해줘.
- POST /orders/:id/cancel: 주문을 취소하고 사용한 포인트를 환급해줘.

4. Flutter 화면
- SHO-01: 카테고리 탭(완제품/밀키트), 상품 카드 리스트, 하단 탭. 상품이 없으면 안내를 보여줘.
- SHO-03: 상품 이미지, 상품·영양 정보, "단축 구매"와 "정기 구독" 버튼. 정기 구독 버튼은 4단계에서 연결하므로 지금은 준비 중 안내만 보여줘.
- SHO-02 단축 구매(바텀시트): 주문 상품 요약, 배송지, 결제 수단, 포인트 사용 입력(전액 사용 포함), 결제하기. 스크롤해도 결제하기 버튼은 화면 하단에 고정해줘.
- 결제 성공 시 주문 완료 안내를 보여주고, 실패하면 주문을 만들지 않고 사유를 보여줘.
```

**완료 기준**
- 탭 전환 시 해당 카테고리 상품만 나온다.
- 포인트를 쓰면 잔액이 줄고 주문 취소 시 돌아온다.
- 클라이언트에서 금액을 바꿔 보내도 서버가 계산한 금액으로 주문된다.
- 포인트 사용 규칙(500P부터 100P 단위)을 위반하면 거부된다. 테스트가 있고 통과한다.

**커밋 메시지:** `feat: 상품 목록·상세, 단축 구매, 포인트 사용, 모의 결제`

## 4단계. 정기구독 · 구독 관리 · AI 추천

화면: SHO-04 정기 구독 설정, SHO-06 구독 해지·일시정지 확인, SHO-05 구독 메뉴 변경, MYP-02 내역 관리, HOM-01·SHO-01의 AI 영역
기능: #7, #15, #16, #17, #20

```
[4단계] 정기구독, 구독 관리, AI 추천을 만들어줘. 3단계의 주문·결제 구조를 재사용해줘.

1. 구독
- subscriptions 테이블(상태 ENUM: 활성/일시정지/해지, 배송 주기 ENUM: 매주/2주마다/4주마다, 배송 요일, 배송지, 결제 수단, 다음 배송일)을 만들어줘.
- POST /subscriptions: 주간 목표 칼로리에 맞는 패키지, 배송 주기, 배송 요일, 결제 수단을 받고 첫 결제를 모의 결제로 처리해줘. 결제가 실패하면 구독을 만들지 않고 사유를 돌려줘.
- 매주 자동 결제 스케줄러는 만들지 말고 다음 배송일 계산과 상태 표시까지만 구현해줘.
- 다음 배송 1회 건너뛰기 API, 일시정지 API, 해지 API를 만들어줘. 해지는 다음 배송일 전날까지만 가능하고, 지나면 400과 사유를 돌려줘.
- 배송지·결제 수단 수정 API. 변경은 다음 회차부터 적용된다.
- 구독 메뉴 변경 API: 전날 섭취 칼로리가 권장 칼로리보다 500kcal 이상 많을 때만 다음 주 메뉴를 더 가벼운 메뉴로 바꿀 수 있고, 배송 확정 전까지만 허용해줘.

2. AI 추천 (Gemini)
- 서버에 AI 모듈을 만들고 두 가지를 제공해줘.
  a. 홈 AI 한마디와 추천 시트: 남은 칼로리·탄단지와 선호 식단 방식으로 저녁 식단 방향을 제안하고 계산 근거("이렇게 계산했어요")를 함께 돌려줘.
  b. 쇼핑 상품 적합도: 상품별 적합도(%)와 "AI 추천" 태그, 부족한 영양소 요약, AI 추천순 정렬.
- 추천은 식단을 기록할 때만 갱신하고, 홈이나 쇼핑에 진입할 때마다 Gemini를 호출하지 마. 결과는 서버 메모리 캐시나 클라이언트 상태에만 두고 DB에는 저장하지 마.
- 호출이 실패하거나 시간이 오래 걸리면 AI 영역을 숨기거나 기본 상품을 보여주고, 호출 중에는 로딩 표시를 보여줘.
- 3단계에서 비워둔 AI 추천순·적합도 정렬을 여기서 채워줘.

3. Flutter 화면
- SHO-04 정기 구독 설정: 패키지, 배송 주기, 배송 요일, 결제 수단, 구독 시작. SHO-03의 정기 구독 버튼을 연결해줘.
- MYP-02 내역 관리: 구독 내역, 배송지 주소 수정, 결제 수단 수정, 구독 해지·일시정지·건너뛰기. 마이페이지 메뉴에서 연결해줘.
- SHO-06 구독 해지·일시정지 확인(모달). 실패하면 기존 상태를 유지하고 사유를 보여줘.
- SHO-05 구독 메뉴 변경(바텀시트): 다음 주 배송 예정 메뉴와 가벼운 메뉴 옵션.
- HOM-01의 AI 한마디와 추천 배너, SHO-01의 AI 영양 요약·적합도 표시를 채워줘.
```

**완료 기준**
- 구독을 만들면 활성 상태로 내역에 보이고, 건너뛰기·일시정지·해지가 확인 후 반영된다.
- 해지 가능 기한이 지나면 거부된다.
- 식단을 기록하면 추천이 바뀌고, 홈 재진입만으로는 Gemini가 호출되지 않는다.
- Gemini 호출이 실패해도 홈과 쇼핑 화면은 정상이다. API 키가 앱 소스와 저장소에 없다.

**커밋 메시지:** `feat: 정기구독, 구독 관리, AI 추천`

## 5단계. 크루 · 프로필 수정 · 알림 설정 · 마무리

화면: CRW-01~08, MYP-04 프로필·목표 수정, MYP-05 알림 설정, HOM-01 크루 미니 배너
기능: #8~#12, #19, #21

```
[5단계] 크루 기능과 나머지 마이페이지 기능을 만들어줘.

1. DB
- crews(이름, 목표, 식단 방식, 정원, 소개), crew_members(역할 ENUM: 크루장/크루원, 상태 ENUM: 신청 대기/가입), crew_posts(사진 경로, 글), crew_comments(응원·댓글, 좋아요), crew_messages(채팅)를 만들어줘.
- users에 알림 설정(식단 리마인드, 크루 인증·응원, 배송 상태) 컬럼을 추가해줘.
- 크루와 사용자는 crew_members로 다대다를 풀고, 한 사용자는 한 크루에만 가입할 수 있게 제약을 걸어줘.

2. 크루 API
- 크루 생성: 생성자를 크루장으로 지정해줘. 정원은 2~20명 범위만 허용한다.
- 크루 검색: 목표 체중, 식단 방식, 인원수 조건. 참가 신청은 "신청 대기"가 되고, 이미 가입했거나 정원이 찬 경우 사유를 돌려줘.
- 크루장만 신청을 수락·거절하고, 크루원을 추방하고, 크루 정보를 수정하고, 크루를 삭제할 수 있다. 권한이 없으면 403.
- 크루장이 탈퇴하면 가장 먼저 가입한 크루원에게 크루장을 넘기고, 남은 인원이 없으면 크루를 삭제해줘.
- 인증 피드: 사진 업로드(multer, 파일 저장소), 글, 좋아요·응원, 오늘 식단 인증 현황. 크루원만 읽고 쓸 수 있다.
- 크루 불꽃: 하루 단위로 크루원 전원이 인증했으면 단계를 1 올리고, 하루라도 전원 인증이 없으면 0으로 초기화해줘.
- 채팅: 메시지 전송과 조회 API. 실시간 소켓은 쓰지 말고 앱이 3초 간격으로 새 메시지를 가져오게 해줘.

3. 프로필·알림 API
- PUT /me/profile을 재사용해 프로필·목표 수정 시 권장 칼로리를 재계산해줘. 과거 기록은 바꾸지 않는다.
- 알림 설정 조회·저장 API. 설정값만 저장하고 실제 푸시 발송은 만들지 않는다.
- 회원 탈퇴 API: 탈퇴 사유를 받고 본인 데이터를 삭제해줘. 크루장이면 위 크루장 탈퇴 규칙을 먼저 적용한다.

4. Flutter 화면
- CRW-03 크루 탐색(진입): 내 크루 카드, 크루가 없으면 크루 찾기 유도, 검색·만들기 버튼.
- CRW-02 검색·참가 신청과 CRW-05 확인 모달. CRW-04 생성과 CRW-06 확인 모달.
- CRW-01 인증 피드: 불꽃 상태, 오늘 인증 현황, 피드, 인증 올리기, 응원.
- CRW-07 크루 채팅: 메시지 리스트와 입력창.
- CRW-08 크루 관리: 정보 수정, 신청 수락·거절, 멤버 목록, 추방, 탈퇴.
- HOM-01의 크루 현황 미니 배너(인증 완료율, 불꽃 상태. 미가입자는 크루 찾기 유도).
- MYP-04 프로필·목표 수정(저장 시 권장 칼로리 재계산), MYP-05 알림 설정(항목별 토글). 마이페이지 메뉴에서 연결해줘.
- 마이페이지에 회원 탈퇴 메뉴를 넣어줘.

5. 마무리
- 모든 화면에서 로딩, 빈 상태, 오류 상태가 빠진 곳을 점검하고 고쳐줘.
- README에 서버·앱 실행 방법, 환경변수, 마이그레이션 적용 순서를 정리해줘.
```

**완료 기준**
- 크루 생성 → 신청 → 수락 → 인증 글 → 응원 → 불꽃 상승 → 채팅 흐름이 끊김 없이 동작한다.
- 크루원이 아닌 사용자는 피드와 채팅을 읽거나 쓸 수 없다.
- 크루장 탈퇴 시 권한이 위임되거나 크루가 삭제된다.
- 새 환경에서 README만 보고 서버와 앱을 실행할 수 있다.

**커밋 메시지:** `feat: 크루(피드·채팅·관리), 프로필·알림, 마무리`
