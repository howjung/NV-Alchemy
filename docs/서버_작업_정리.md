# 서버 작업 정리 (프론트 담당 → 백엔드 팀원)

`backend` 브랜치에 올라온 서버 코드를 기준으로, 프론트 쪽에서 서버에 **무엇을 바꿨고 왜 바꿨는지**, 그리고 **백엔드 팀원이 확인해야 할 것**을 정리한 문서다. 인증 동작 원리는 `docs/인증_설명.md`에 따로 있다.

## 1. 한눈에 보기

- 작업 브랜치: `feat/backend-extend` (`backend`에서 갈라져 나온 브랜치. `backend`는 건드리지 않았다)
- 커밋 2개
  1. `0740799` Postgres 없이 실행하는 개발 모드, DB 접속 정보 환경 변수화
  2. `e77f75e` 서버 인증, 본인 데이터만 접근, 입력 검증
- 합치는 방법: `feat/backend-extend` → `backend` PR (팀원 확인 후)

## 2. 왜 바꿨나

| 기존 서버의 문제 | 바꾼 내용 |
| --- | --- |
| 로그인이 없고, 요청마다 `userId`를 앱이 직접 적어 보냈다. 값을 바꾸면 남의 기록을 보고 지울 수 있었다 | 가입·로그인과 토큰 도입. `userId`는 토큰에서 꺼낸다 |
| `GET /weights`, `GET /meals`가 모든 사용자의 기록을 돌려줬다 | 목록·조회·수정·삭제 모두 내 기록만. 남의 기록은 404 |
| 입력 검증이 없었다 | PRD 7장 기준 범위 검사(아래 표) |
| Postgres가 있어야만 서버가 떴고 접속 정보가 코드에 박혀 있었다 | 환경 변수로 변경, `DB_TYPE=sqljs`면 Postgres 없이 실행 |

## 3. 실행 방법

```bash
git checkout feat/backend-extend
npm install
cp .env.example .env      # DB_TYPE=sqljs, JWT_SECRET 포함
npm run start:dev         # http://localhost:3000
npm run test:smoke        # 다른 터미널에서 실행. 인증·범위·남의 기록 차단 확인
```

- `.env`의 `DB_TYPE=sqljs`: 로컬 파일 `dev.sqlite`에 저장(git 제외). Postgres를 쓰려면 이 줄을 지우고 `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`을 채운다. 기본값은 기존 코드의 값과 같다.
- `JWT_SECRET`은 필수다. 없으면 서버가 시작되지 않는다.
- `GEMINI_API_KEY`는 사진 분석(`POST /meals/upload`)에만 필요하다. 키는 각자 `.env`에 넣고 git에는 올리지 않는다.

### Docker로 Postgres 실행 (팀원과 같은 환경)

```bash
docker run -d --name antifreeze-db -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=antifreeze_db \
  -v antifreeze-data:/var/lib/postgresql/data postgres:16
```

- `.env`에서 `DB_TYPE=sqljs` 줄을 지우거나 주석 처리하면 서버가 이 Postgres에 붙는다.
- 재부팅 후에는 Docker Desktop을 켜고 `docker start antifreeze-db`.
- 이 방식으로 서버를 띄워 `npm run test:smoke` 통과를 확인했다(2026-11-20).

## 4. API 목록

로그인이 필요한 API는 요청 헤더에 `Authorization: Bearer <토큰>`을 붙인다.

| 메서드 | 경로 | 로그인 | 설명 |
| --- | --- | --- | --- |
| POST | `/auth/signup` | 불필요 | 이메일·비밀번호·닉네임으로 가입, 토큰 발급 |
| POST | `/auth/login` | 불필요 | 로그인, 토큰 발급 |
| GET | `/users/me` | 필요 | 내 정보 |
| PATCH | `/users/me` | 필요 | 닉네임·성별·생년월일·키·목표 체중·목표 칼로리 수정 |
| DELETE | `/users/me` | 필요 | 탈퇴(계정·체중·식단 삭제) |
| POST/GET | `/weights` | 필요 | 체중 기록 등록(같은 날은 덮어쓰기)·내 목록 |
| GET/PATCH/DELETE | `/weights/:id` | 필요 | 내 기록만 |
| POST/GET | `/meals` | 필요 | 식단 기록 등록·내 목록 |
| GET/PATCH/DELETE | `/meals/:id` | 필요 | 내 기록만 |
| POST | `/meals/upload` | 필요 | 사진 1장(`file` 필드) → Gemini 분석 결과와 `imageUrl` |

### 입력 규칙 (PRD 7장 기준)

| 항목 | 규칙 | 어기면 |
| --- | --- | --- |
| 비밀번호 | 8자 이상 | 400 |
| 닉네임 | 2~12자 | 400 |
| 이메일 | 형식 검사, 중복 불가 | 400 / 409 |
| 키 | 100~250cm | 400 |
| 체중·목표 체중 | 20~300kg | 400 |
| 생년월일 | 만 14~100세(최소 가입 연령 만 14세) | 400 |
| 끼니 | 아침·점심·저녁·간식 | 400 |

DTO에 없는 항목(예: body의 `userId`)은 자동으로 버려진다.

## 5. 백엔드 팀원이 확인해 줄 것

1. **기존 API가 바뀌었다.** `/users` CRUD와 `userId`를 body로 받던 방식이 사라졌다. 이 API를 이미 쓰는 코드가 있으면 알려 달라.
2. **엔티티가 바뀌었다.** `User`에 `passwordHash`, `gender`, `birthDate`, `heightCm`이 추가됐다. `synchronize: true`라서 공용 Postgres에 연결하면 테이블이 자동으로 바뀐다. 공용 DB에 붙이기 전에 합의가 필요하다.
3. **작업이 겹치는지**: `user.entity.ts`, `app.module.ts`, `main.ts`를 팀원이 동시에 수정 중이면 PR에서 충돌이 난다.
4. **jest 단위 테스트는 지웠다.** 원래 설정(ESM 문제)으로 7개 모두 실행 실패 상태였고, 인증을 바꾸면 어차피 깨지는 테스트였다. 대신 `npm run test:smoke`를 쓴다. jest를 고칠 계획이면 알려 달라.
5. **패키지 추가**: `@nestjs/jwt`, `class-validator`, `class-transformer`, 개발용 `sql.js`.

## 6. 아직 없는 것 (앞으로 할 일)

| 우선순위 | 항목 | 비고 |
| --- | --- | --- |
| 1 | 앱 로그인·가입 화면을 이 서버에 연결 | 프론트 작업. 서버 주소는 `--dart-define`으로 받을 예정 |
| 2 | 비밀번호 변경·재설정, 토큰 재발급(refresh)·로그아웃 폐기 | 지금은 토큰이 7일간 유효 |
| 3 | 로그인 시도 횟수 제한 | `@nestjs/throttler` |
| 4 | 사진 업로드 제한 | PRD 확정: JPG/PNG, 10MB. 지금은 검사가 없다 |
| 5 | 쇼핑·주문·포인트·배송지·카드 | 카드는 끝 4자리·브랜드만 저장(PRD 확정) |
| 6 | 소셜(게시물·크루·신고·차단) | 앱 화면은 구현됨, 서버 API는 없음 |
| 7 | 운영 전 점검 | `synchronize: true`를 마이그레이션으로, `JWT_SECRET` 운영값, CORS 제한 |

## 7. 확인하지 못한 것

- 팀원의 Postgres 설정을 직접 확인하지는 못했다. 위 Docker 설정은 서버 코드의 기본 접속 정보에 맞춘 것이다.
- 사진 분석은 Gemini 키가 없어서 실행하지 못했고, 코드의 모델 ID `gemini-3.0-flash`가 실제로 존재하는지도 확인하지 못했다.
- 앱에서 이 서버를 호출해 본 적은 아직 없다.
