### 3-3. 앱 흐름 점검에서 나온 개선 제안 (v24)

실제 앱을 눌러 본 범위: 로그인, 홈(알림·포인트), 기록, 소셜 첫 화면, 쇼핑(담기→장바구니→결제→주문 완료→주문 내역→상세), 프로필 토스트·회원 탈퇴. 아직 안 눌러 본 곳: 회원가입·온보딩, 비밀번호 재설정, 식단 기록 시트, 크루 가입·게시물 작성·피드, 프로필 하위 화면 대부분.

1. 로그인이 입력값과 상관없이 홈으로 이동한다(빈 입력도 통과). 최소한 빈 입력 안내가 필요하다(PRD에 로그인 실패 문구가 없어 확정 필요).
2. 포인트 잔액(2,500P)이 홈·프로필·쇼핑에 각각 따로 있다. 쇼핑에서 포인트를 써도 홈·프로필·포인트 내역에 반영되지 않는다. 공유 데이터로 합친다.
3. 주문 완료 화면과 주문 내역 행에 수량과 주문일이 없다(상세에는 있음).
4. 장바구니 드롭다운에 수량(×3)이 없고 상품명만 나온다.
5. 결제하기 버튼이 비활성인 이유(동의 체크)가 버튼 근처에 안 보인다.
6. 새 배송지 추가·새 카드 등록은 프로필 목록 화면이 열려 "추가"를 한 번 더 눌러야 한다. 추가 화면으로 바로 열면 단계가 줄어든다.
7. 알림 목록 항목을 눌러도 이동하지 않는다(보상·크루 알림은 해당 화면으로 연결하면 좋다).

1. **시작 전 동기화:** `git fetch origin` 후 새 커밋과 겹치는 파일을 확인하고, 필요하면 병합한다. 강제 푸시는 하지 않는다.
2. **지침:** `flutter_apps/AGENTS.md`(변경은 최소로, 인접 코드 건드리지 않기)를 따른다.
3. **Figma 기준:** 시트 프레임(P1~P5 등)은 "원본"이고 실제 화면은 `Overlay/…` 프레임을 기준으로 한다. Figma에 없는 상태는 임시 디자인으로 표시하고 작업 이력의 "Figma에 없어서 임시로 만든 것"에 추가한다.
4. **공용 위젯 먼저 재사용:** `showConfirmPopup`(`cancelLabel` 옵션 있음), `AppMenu`/`AppMenuItem`(`core/widgets/app_overlays.dart`), `PostActionRow`, `PostInteractionStore`.

   - `docs/프론트엔드_작업이력.md`: 상단 버전 +1, 이력 한 줄, 구현 상태 표 갱신. 커밋 해시는 커밋 후에 채운다(해시 기입용 후속 커밋을 따로 만든다).
   - 구현 내용이 PRD와 관련되면 `docs/PRD_Antifreeze.md`도 버전을 올리고 이력 행을 추가한다. 확정되지 않은 값은 "(제안값)", "(확정 필요)"로 남기고 임의로 "확정"이라 쓰지 않는다.

6. **푸시 전:** `flutter analyze`(이슈 없음)와 `flutter test`(전체 통과)를 통과시킨다. 커밋 메시지는 `feat:`/`fix:`/`docs:` 접두어와 한국어 설명을 쓴다.

## 5. 화면에서 직접 확인하는 방법 (macOS)

위젯 테스트는 창 크기와 앱 폭이 같아서 폭 계산 오류를 놓칠 수 있다(토스트 위치 문제가 실제로 그랬다). 시각 변경은 앱을 실행해 확인한다.

- 실행: `cd flutter_apps && flutter run -d macos`. 앱 폭은 402다.
- 핫 리스타트: `flutter_tools` 프로세스에 `kill -USR2 <PID>`. 핫 리스타트하면 로그인 화면으로 돌아간다(로그인 후 해당 탭으로 이동).
- 스크린샷: `screencapture -R<x>,<y>,<w>,<h> 파일.png`. 앱 창 위치는 `osascript`로 조회한다.
- 클릭 도구: 세션 임시 폴더의 `tools/click`(Swift CGEvent)과 `tools/sc.sh x y`(앱이 맨 앞일 때만 클릭)를 썼다. 임시 폴더는 초기화될 수 있으니 없으면 새로 만든다. 다른 앱 창으로 클릭이 빗나가지 않게 반드시 맨 앞 앱을 확인한다.
- Figma MCP: 파일 키 `gkRodOTSAWJ7EeRMANmERf`, 프레임은 402×874. `create_session` 후 `get_metadata`, `get_screenshot`, `get_design_context`를 쓴다. 세션 ID는 만료될 수 있으니 새로 만든다.
