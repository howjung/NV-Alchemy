# Antifreeze 확정 필요 체크리스트

**버전: v2** (기준: PRD v8 9장, 프롬프트 v6). v1에서 개수 오류, 단계 배정 오류, 근거 없는 추천값을 독립 검토로 확인해 고쳤다.

## 읽는 법

- PRD 본문에 "(확정 필요)"가 79번 나오지만 같은 항목이 반복된다. PRD 9장 표는 **44행**이고, 아래 체크리스트는 N1·N19 등을 화면·단계별로 나눈 **53줄**이다(단계별 9 / 10 / 8 / 13 / 13).
- 각 항목은 **그 단계 프롬프트를 실행하기 전에** 정해야 하는 시점으로 묶었다.
- 값의 상태는 세 가지로 적는다.
  - **미정**: 근거가 없어 제안하지 않는다. 팀이 정한다.
  - **임시**: 지금 프롬프트가 쓰는 값이다. 확정이 아니며 바꾸면 해당 단계 프롬프트도 고친다.
  - **제안**: 검토에서 나온 안이다. 근거가 약하므로 팀이 확정해야 한다.
- **[법·개인정보·결제]** 표시가 붙은 항목은 팀이 확정하기 전에는 제안값을 쓰지 않는다. 법적 근거는 이 문서들만으로는 확인되지 않았다(미확인).
- 확정하면 PRD 해당 위치를 고치고 버전을 올린다(v9~). 프롬프트의 임시값도 맞춘다.

## 검토에서 새로 발견된 결정 사항 (PRD 9장에 아직 없음)

독립 검토 중 나온 항목이다. PRD에는 미결로 적혀 있지 않으므로 v9에 옮긴다. Figma 관련 지적은 검토자가 추출 텍스트만 보고 한 것이므로 Figma에서 먼저 확인한다.

- [ ] **탄단지 목표 산식** — PRD에 산식이 없다. Figma 샘플(2,442kcal, 탄 256g·단 128g·지 64g)은 256×4+128×4+64×9=2,112kcal라서 서로 맞지 않는다. 비율을 정하고 Figma 숫자는 예시로만 쓴다(1·2단계 전)
- [ ] **S1 "남은 탄단지" 표시** — Figma가 섭취량과 같은 값을 "남음"으로 쓴 것으로 보인다. 남은 = 목표 − 섭취로 고정하고 디자인 수정 여부 확인(3단계 전)
- [ ] **3단계 의존 해소** — S4 주문·결제가 배송지·결제 수단을 쓰는데 관리 화면은 4단계다. 시드로 대신할지 3단계로 옮길지(프롬프트는 시드 방식, 3단계 전)
- [ ] **비밀번호 재설정 화면** — 링크를 연 뒤의 새 비밀번호 입력 화면이 71개 화면 목록에 없다. 화면 추가 또는 모의 처리(프롬프트는 API만, 1단계 전)
- [ ] **식단 인증의 정의** — PRD는 "사진 + 식단 선택 + 한마디"인데 SOC-02에는 식단 선택 UI가 없다. 인증 = 크루 게시물 1건으로 둘지, 비공개 게시물·비디오가 인증으로 인정되는지(5단계 전)
- [ ] **크루 연속 인증 판정 방식** — 임시: 스케줄러 없이 조회 시 날짜로 계산(프롬프트 v6). 중간 가입자·추방자의 분모 처리(5단계 전)
- [ ] **PRD H7 조건** — 프롬프트 v6은 "직전 연속이 1일 이상이었다가 끊긴 경우"로 정정했다. PRD 4.10 수락 기준도 같이 고쳐야 한다
