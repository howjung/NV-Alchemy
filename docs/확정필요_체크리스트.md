# Antifreeze 확정 필요 체크리스트

기준: PRD v8 9장. 본문에 "(확정 필요)"가 79번 나오지만 같은 항목이 여러 곳에 반복되어, 실제로 정할 항목은 **44개**다(9.1 3개 + 9.2 N1~N25 25개 + 9.3 16개).
각 항목은 **어느 단계 프롬프트를 돌리기 전에** 정해야 하는지로 묶었다. "추천"은 정하기 어려울 때 그대로 써도 되는 값이며, 사람이 확정한 값이 아니다.
확정하면 PRD 해당 위치를 고치고 버전을 올린다(v9~). 프롬프트 파일의 임시값도 같이 맞춘다.

---

## 1단계 전 (서버·DB·인증·온보딩·약관)

- [ ] **N23** 최소 가입 연령. Figma 생년월일 범위는 만 10~100세로 보임. 추천: 만 14세 이상
- [ ] **N21** ONB-02 "목표 변화(-6kg)"와 "목표 체중"의 관계. 추천: 목표 체중을 입력값, 목표 변화는 계산값으로 표시
- [ ] **N22** 선호 식단 방식을 온보딩에서 정하는지. 추천: 온보딩에서는 묻지 않고 기본값 "혼합", 프로필 06에서 변경
- [ ] (9.1) BMR 공식·활동량 계수·하한선. 추천: Mifflin-St Jeor, 계수 1.2/1.375/1.55/1.725, 하한 남 1500 / 여 1200 (이미 PRD 제안값)
- [ ] (9.3) 활동량 선택지 이름, 목표 감량을 권장 칼로리에 반영할지. 추천: 반영 안 함(유지 칼로리만 계산)
- [ ] (9.3) 알레르기·기피 음식 데이터를 받을지. 추천: 이번 범위에서 제외
- [ ] (9.3) 입력 중 뒤로 가기 시 임시 저장 여부. 추천: 저장하지 않고 확인 팝업만
- [ ] **N19 일부** 약관·개인정보 처리방침·오픈소스 라이선스 본문 출처. 추천: 샘플 문구 시드

## 2단계 전 (홈·기록·포인트 적립·연속 기록·알림 목록)

- [ ] (9.1) 음식 데이터 출처. 추천: 자체 시드 30개 → 필요하면 공공 DB로 확장
- [ ] (9.1) 체중 하루 1회 제한. 추천: 하루 1회, 같은 날 다시 입력하면 덮어쓰기
- [ ] **N25** 식단 기록 시트 안 음식 검색·직접 입력 방식과 음식 DB 시드 범위
- [ ] (9.3) 소급 기록 허용 여부. 추천: 오늘만 허용
- [ ] (9.3) 개인 일/주 적립 한도. 추천: 한도 없음(하루 첫 기록 5P, 1일 1회라 사실상 일 5P)
- [ ] **N11** 연속 기록 마일스톤 캐릭터 꾸미기 보상의 종류와 포인트 병행 여부. 추천: 꾸미기 아이템 이름만 시드, 포인트 보너스 없음
- [ ] **N24** 성장 보상 도움말 시트(SHT-P01)를 여는 위치. 추천: 홈 연속 기록 칩 탭
- [ ] **N20** 알림 종류별 생성 시점, 기록 리마인드 시각. 추천: 서버 이벤트 발생 시 즉시 생성, 리마인드 20:00 KST
- [ ] (9.3) 사진 한 장 칼로리 분석 포함 여부. 추천: 제외(Figma에 화면 없음)

## 3단계 전 (쇼핑·가격 비교·장바구니·주문·결제·포인트 사용)

- [ ] **N2** 판매처별 가격을 예시 데이터로 둘지 실제 수집할지. 추천: 예시 데이터 시드
- [ ] **N3** 장바구니의 판매처 선택 방식, 판매처가 다른 상품의 배송비·주문 분리. 추천: 판매처별로 주문을 나누고 배송비도 판매처별 부과
- [ ] (9.1) 결제 범위(실결제/모의), 결제 실패 재시도. 추천: 모의 결제, 실패 시 같은 화면에서 재시도
- [ ] (9.3) 포인트 사용 우선순위(4.4는 P2, S4 화면은 P1). 추천: S4 결제에 포인트 사용을 포함해 P1로 올림
- [ ] **N1 일부** 상품 상세 시트 내용(상품·영양 정보 항목). 추천: 이름, 판매처, 가격, 칼로리, 탄·단·지, 설명
- [ ] (9.1) 과식 기준 500kcal(3·4단계에서 사용). 추천: 현재 제안값 유지

- [ ] **N6** 주문 취소 가능 조건. 추천: 결제완료 상태에서만 취소 가능, 취소 시 사용 포인트 환급
- [ ] **N7** 구독 결제 포인트 사용을 매 회차 쓰는지 첫 회만인지. 추천: 첫 회만

- [ ] **N9** 배송지·결제 수단 입력 항목, 카드 정보 저장 범위. 추천: 카드는 마지막 4자리와 브랜드만 저장
- [ ] (9.3) 적합도 계산 주체. 추천: 규칙으로 계산, Gemini는 추천 문구 생성만

- [ ] (9.3) 선호 식단 방식 변경 시 즉시 재계산 여부. 추천: 즉시 재계산
- [ ] **N1 일부** 프로필 05 알림 설정, 프로필 06 항목 구성. 추천: 토글 3개(기록 리마인드, 크루, 혜택)
- [ ] (9.3) 푸시 실제 발송 여부. 추천: 이번 범위는 설정 저장만

## 우선 처리 순서

1. **지금 당장**: 1단계 전 항목 중 N21~N23만 정하면 시작 가능
2. **1단계 진행 중**: 2단계 전 항목, 특히 N25와 N11
3. **2단계 진행 중**: 3단계 전 항목(결제 범위, N2, N3)
4. **3단계 진행 중**: 4단계 전 항목(N4~N9, AI 5개)과 N1 상세 확인
5. **4단계 진행 중**: 5단계 전 항목

## 참고

- 단계 배정은 프롬프트 파일의 단계 제목 기준이다. 항목 중 일부(예: 사진 용량)는 2단계 기록과 5단계 업로드에 걸쳐 있어 더 앞선 단계에 두었다.
- 기존 PRD 9.4의 임시값(자체 시드 30개, 모의 결제, 1인 1크루 등)과 이 문서의 추천은 같은 방향으로 맞췄다.
